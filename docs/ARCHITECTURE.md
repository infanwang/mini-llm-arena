# 架构与技术设计

本平台的核心在于“**如何用统计方法从充满噪声的交互数据中提取稳健的能力排名**”。以下是核心设计的简述。

## 1. 评分引擎：Bradley-Terry 模型

平台不使用绝对打分，而是基于成对比较的 Bradley-Terry (BT) 模型：
`P(i 胜 j) = σ(β_i - β_j) = 1 / (1 + e^{-(β_i - β_j)})`

- 使用 `L2` 正则化的 Logistic Regression 求解 MLE，防止完全分离的数据导致拟合发散。
- **成对 Bootstrap**：按“对战”进行重采样（而非按投票），拟合 1000 次以获得模型得分与排名的置信区间。

## 2. 协变量校正 (Style Control)

人类评审者容易受回答长度和格式（如 Markdown 列表）干扰。模型设计中包含了协变量：
`P(A ≻ B) = σ( β_A − β_B + γ_len·(len_A − len_B) + γ_pos·1[A_first] )`

拟合时同时估计 `γ_len`（长度偏好）与 `γ_pos`（位置偏好），并在排行榜展示中剥离这些偏差。

## 3. 两阶段采样策略

为了在有限的投票预算下最大化信息增益，平台采用了不同于随机配对的策略：
- **Placement Phase**：新模型进入时，通过与现有模型进行二分搜索（基于当前得分）快速确定其大致位置，复杂度从 O(M) 降至 O(log M)。
- **Steady Phase**：稳态阶段优先选择评分相近的模型进行配对（Proximity Sampling），并通过保留小比例的全局随机配对维持图的连通性。

## 4. 防作弊机制

- **前置过滤**：对用户输入的 Prompt 进行规范化（剥离零宽字符、解码 Base64、NFKC 折叠）。若命中“身份探测”模式，直接拒绝进入竞技。
- **后验降权**：若投票者在极短时间内完成投票，或针对单一模型存在高度一致的协同投票模式，该投票将被标记为 `suspicious`，在拟合时权重降为 0.3。

## 5. 数据流转

1. `POST /battles` 触发采样器，分配两个匿名模型并发推理。
2. 返回给前端匿名响应（A/B），模型身份以 Hash 形式存入数据库。
3. `POST /battles/{id}/vote` 接收投票，并触发去匿名化（解密模型 ID）。
4. Celery 定时任务或手动执行 `make rating` 触发评分引擎，读取增量投票并生成新的快照。
